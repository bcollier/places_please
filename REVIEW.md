# Code Review Against `SPEC.md`

1. **[PASS] Static project health checks pass.** `npx tsc --noEmit`, `npx expo lint`, and `npx expo-doctor` all completed successfully; Expo Doctor reported 20/20 checks passing. The package versions are internally consistent with Expo SDK 58 (`package.json:9-40`).

2. **[PASS] The app implements script capture from a camera or photo library.** `takePhoto` requests camera permission and launches the camera, while `choosePhotos` supports ordered multi-selection (`src/lib/script-import.ts:31-57`). The import screen exposes both paths and lets the user review/remove pages before processing (`src/app/scripts/new.tsx:191-252`). Images are resized and compressed before upload (`src/lib/script-import.ts:106-117`), which is appropriate for a mobile app.

3. **[PASS] PDF and modern Word document import are implemented.** The picker accepts PDF and DOCX and rejects legacy `.doc` files with a useful message (`src/lib/script-import.ts:59-88`). The Edge Function extracts PDF text with `unpdf` and DOCX text from `word/document.xml` (`supabase/functions/places-ai/index.ts:230-297`); scanned PDFs fall back to model-based parsing (`src/lib/script-import.ts:198-222`). This satisfies the spec's PDF/Word criterion, with `.docx` as the supported Word format.

4. **[PASS] AI-assisted script parsing and AI line transcription are implemented through a server-side OpenRouter client.** The mobile client invokes only the Supabase Edge Function (`src/lib/ai.ts:21-92`), and the OpenRouter secret is read only in the server function (`supabase/functions/places-ai/index.ts:989-1015`). Script parsing covers images, extracted text, and scanned PDFs (`supabase/functions/places-ai/index.ts:366-456`); spoken lines are sent for verbatim transcription (`supabase/functions/places-ai/index.ts:918-975`).

5. **[PASS] Run Lines implements the requested partner/read/pause/listen loop.** Partner lines are spoken and the user's lines start the recorder (`src/lib/rehearsal/line-runner.ts:215-247`, `src/lib/rehearsal/line-runner.ts:280-330`). The UI exposes pause/resume, retry, continue, “Line!”, and “I'm done” controls (`src/app/scripts/[id]/run.tsx:172-218`).

6. **[PASS] The three requested correctness outcomes and distinct feedback sounds are implemented.** Word-level edit distance produces `perfect`, `close`, and `missed`, with a 75% close threshold (`src/lib/scoring.ts:116-148`). The runner plays separate perfect/close/miss assets and matching haptics (`src/lib/rehearsal/line-runner.ts:356-373`; `src/lib/audio/sfx.ts:3-12`). Perfect ignores case and punctuation, which is a reasonable interpretation of “word perfect.”

7. **[WARN] Warm Up exists, but it is not guaranteed to be genuinely multiple-choice.** Cue/answer pairs and shuffled distractors are implemented (`src/lib/rehearsal/warmup.ts:24-47`), and the screen displays/selects choices with correct/incorrect feedback (`src/app/scripts/[id]/warmup.tsx:161-209`). However, `warmupAvailable` only requires one cue pair and three total lines (`src/lib/rehearsal/warmup.ts:50-53`), while distractor generation can run out of distinct alternatives (`src/lib/rehearsal/warmup.ts:31-46`). A small or repetitive script can therefore produce only the correct answer, so the spec's multiple-choice behavior is not correct for every accepted round.

8. **[PASS] Listen mode implements a two-sided dialogue reading.** It casts per-character voices and reads each line in order (`src/lib/rehearsal/listen-player.ts:58-93`). Users can have their own lines read or leave timed gaps to speak them (`src/lib/rehearsal/listen-player.ts:84-89`; `src/app/scripts/[id]/listen.tsx:163-179`).

9. **[PASS] The Home screen provides the required overview and direct navigation to all three modes.** It presents the current script plus Run Lines, Warm Up, and Listen tiles (`src/app/index.tsx:97-139`) and uses Expo Router for navigation (`src/app/index.tsx:54-61`; `src/app/_layout.tsx:79-108`).

10. **[PASS] The standard-user-only role model is implemented.** Users start as anonymous Supabase users and can optionally convert to an email account (`src/providers/auth-provider.tsx:8-18`, `src/lib/account.ts:7-20`). There is no administrator UI or app role.

11. **[PASS] Supabase/Postgres persistence covers the required entities.** `auth.users` plus `places_profiles` represent users, and migrations define `places_scripts` and `places_practice_history` (`supabase/migrations/20261122000000_places_please.sql:9-16`, `supabase/migrations/20261122000000_places_please.sql:34-45`, `supabase/migrations/20261122000000_places_please.sql:68-85`). Row-level security restricts reads and writes to the owning user (`supabase/migrations/20261122000000_places_please.sql:18-25`, `supabase/migrations/20261122000000_places_please.sql:49-58`, `supabase/migrations/20261122000000_places_please.sql:90-97`).

12. **[PASS] The design system uses Carnegie Mellon colors and deliberate typography.** The palette defines Carnegie Red and CMU secondary colors (`src/constants/theme.ts:11-22`), applies them to light/dark semantic tokens (`src/constants/theme.ts:24-65`), and provides consistent serif/sans typography variants (`src/components/ui/text.tsx:22-89`). “Beautiful” remains subjective, but the branding and typography acceptance criteria are concretely implemented.

13. **[PASS] iOS is configured as a first-class target.** The app has an iOS bundle identifier and iOS icon (`app.json:10-17`), iOS-safe audio routing/recording options (`src/lib/audio/line-listener.ts:16-42`), and Keychain-backed auth storage (`src/lib/secure-storage.ts:4-15`). The extra Android/web code does not prevent the specified iOS target from working.

14. **[PASS] The code implements screen-off listening and rehearsal using the SDK 58 background-audio requirements.** The Expo Audio config plugin enables background playback and recording (`app.json:42-48`), and runtime audio mode enables `shouldPlayInBackground` plus background recording for practice (`src/lib/audio/session.ts:17-27`). A looping silent player keeps the audio session active between lines/network calls (`src/lib/audio/session.ts:30-40`). This matches the [Expo SDK 58 Audio documentation](https://docs.expo.dev/versions/v58.0.0/sdk/audio/) for iOS. This is a code/configuration pass; no physical-device lock-screen test was present in the repository.

15. **[FAIL] The literal offline-behavior criterion is not enforced.** The spec says the app “can't be used offline,” but the app intentionally loads scripts/settings from AsyncStorage before contacting Supabase (`src/providers/data-provider.tsx:53-76`), caches synthesized audio on device (`src/lib/audio/tts.ts:236-270`), offers explicitly offline iPhone voices (`src/app/settings.tsx:98-108`), and Warm Up is entirely local after a script is loaded (`src/lib/rehearsal/warmup.ts:24-53`). AI parsing and transcription still require connectivity, but significant parts of the app remain usable offline, contrary to the stated behavior.

16. **[FAIL] The OpenRouter analytics criterion does not guarantee that every sent call is logged.** Each attempt is written only after an HTTP response/error/timeout (`supabase/functions/places-ai/index.ts:1005-1085`); there is no database record at send time. If the Edge Function terminates while the request is in flight, the call and possible cost disappear. In addition, `logCall` deliberately lets a failed database insert leave the paid request successful (`supabase/functions/places-ai/index.ts:1091-1123`). The response usage cost is correctly taken from OpenRouter's actual `usage.cost`, but the “all calls” guarantee is not met. Paid-call audit:
    - `[SENT: NOT LOGGED] [RECEIVED: LOGGED] [COST: LOGGED] [NO FALLBACK] supabase/functions/places-ai/index.ts:418` — OpenRouter script parsing; `google/gemini-3.8-flash` is currently $0.83/$4.12 per 1M input/output tokens and `google/gemini-2.5-flash` fallback is $0.30/$2.50.
    - `[SENT: NOT LOGGED] [RECEIVED: LOGGED] [COST: LOGGED] [FREE FALLBACK] supabase/functions/places-ai/index.ts:885` — OpenRouter gender guessing; `google/gemini-3.5-flash-lite` is currently $0.30/$2.50 per 1M input/output tokens with `google/gemini-2.5-flash` fallback at $0.30/$2.50. If guessing fails, voice casting actually falls back to alternating local voice genders (`src/lib/audio/tts.ts:132-151`).
    - `[SENT: NOT LOGGED] [RECEIVED: LOGGED] [COST: LOGGED] [NO FALLBACK] supabase/functions/places-ai/index.ts:953` — OpenRouter transcription; the same two models/prices apply. A failed transcription is skipped rather than checked locally (`src/lib/rehearsal/line-runner.ts:332-350`).
    - Shared response/failure logging is at `supabase/functions/places-ai/index.ts:1021-1073`; actual usage and cost persistence is at `supabase/functions/places-ai/index.ts:1104-1120`. Prices were checked against OpenRouter's live model list on 2026-11-22.

17. **[WARN] The optional paid Azure TTS fallback records an estimate, not billed usage, and also has no send-time record.** The request is issued at `supabase/functions/places-ai/index.ts:515-525`; success/failure is logged afterward (`supabase/functions/places-ai/index.ts:527-539`). Cost is calculated from text length and the configured list-price constant (`supabase/functions/places-ai/index.ts:51`, `supabase/functions/places-ai/index.ts:533-568`), so the paid-call classification is `[SENT: NOT LOGGED] [RECEIVED: LOGGED] [COST: ESTIMATE ONLY] [FREE FALLBACK]`; the app falls back to device speech (`src/lib/audio/tts.ts:331-342`).

18. **[FAIL] A failed guest-to-email data merge can strand the user's existing scripts.** Account switching captures a snapshot and guest token, signs into the new account, and only then copies data (`src/lib/account.ts:45-63`). If copying fails, it reports that the scripts remain under the old guest session (`src/lib/account.ts:63-69`), but the Supabase client has already replaced that guest session and the code provides no rollback or way to restore the old guest token. The old rows may still exist server-side, yet they are no longer accessible through the app. This violates the “unbreakable”/data-safety constraint.

19. **[FAIL] Account changes can race stale data requests and write the wrong user's local snapshot.** `refresh` has no request generation, cancellation, or check that the captured `userId` is still current before setting scripts/settings (`src/providers/data-provider.tsx:38-51`). When authentication changes, the hydration effect cancels only the local-load continuation, not the in-flight Supabase refresh (`src/providers/data-provider.tsx:53-70`). A late guest response can overwrite the newly signed-in account's state and, once `hydratedUser` is the new ID, be persisted under the new user's AsyncStorage key (`src/providers/data-provider.tsx:72-76`).

20. **[FAIL] The post-sign-in success flow calls `refresh` with the stale guest ID.** `SaveAccount` captures `refresh` before the OTP changes users and calls it after `verifyEmailCode` returns (`src/app/account.tsx:30-47`, `src/app/account.tsx:70-73`). That callback still closes over the guest `userId` used by `DataProvider.refresh` (`src/providers/data-provider.tsx:38-51`). `listScripts` will use the new active Supabase session while `getProfile(userId)` asks for the old guest profile; the subsequent upsert can fail RLS (`src/lib/api.ts:149-165`). The merge may have succeeded, but the success alert/navigation can fail or the UI can show inconsistent data.

21. **[FAIL] Run Lines and Listen leave the background audio session active after runtime errors.** Both flows configure background audio and start the silent keep-alive (`src/lib/rehearsal/line-runner.ts:119-123`; `src/lib/rehearsal/listen-player.ts:63-66`). Their catch blocks set an error state without calling `releaseAudioSession` (`src/lib/rehearsal/line-runner.ts:133-137`; `src/lib/rehearsal/listen-player.ts:94-98`). Until the screen unmounts or the user explicitly retries/stops, silent background playback and the recording-capable audio session can remain active, wasting battery and interfering with other audio.

22. **[FAIL] A failed practice-history save is permanently treated as saved for that run.** `useSessionSaver` sets `savedRef.current = true` before attempting the database insert (`src/hooks/use-session-saver.ts:13-20`). On failure it only stores an error message and never resets the flag (`src/hooks/use-session-saver.ts:20-23`), so cleanup and repeated save calls refuse to retry (`src/hooks/use-session-saver.ts:15-16`, `src/hooks/use-session-saver.ts:33`). A transient network error therefore loses the session despite the persistent `practice_history` requirement.

23. **[FAIL] Listen-mode history undercounts, omits, or overcounts lines.** `saveSession` refuses to save when `maxIndex.current === 0`, so listening to only the first line—or completing a one-line script—creates no history (`src/app/scripts/[id]/listen.tsx:46-57`). It records `maxIndex + 1` rather than the number of lines actually heard, so starting at line 10 immediately claims 11 lines (`src/app/scripts/[id]/listen.tsx:46-56`, `src/app/scripts/[id]/listen.tsx:78-83`). This makes `places_practice_history.lines_total` unreliable.

24. **[WARN] Canceling script processing does not cancel the underlying network request or its cost.** The cancel token is checked before/after steps (`src/lib/script-import.ts:102-104`, `src/lib/script-import.ts:122-149`), but `src/lib/ai.ts:21-23` invokes the Edge Function without an abort signal. The UI returns immediately (`src/app/scripts/new.tsx:93-96`), while the OpenRouter request can continue to completion and incur/log cost. This is especially relevant for the 280-second client timeout used by parsing (`src/lib/ai.ts:67-72`).

25. **[WARN] Critical logic has no automated tests.** No test files or test script are present (`package.json:49-56`). Scoring, chunk merging, warm-up distractors, account migration, history saving, cancellation, and background-audio state transitions are all behavior-heavy and currently protected only by type-check/lint. This is a material risk for the spec's “dead simple” and “unbreakable” constraint.

26. **[WARN] Production dependencies currently include a reported moderate-severity transitive vulnerability.** `npm audit --omit=dev` reports three moderate findings for `minimatch` through `@expo/fingerprint`/Expo; Expo is declared at `package.json:9`. The audit's proposed automatic fix would downgrade Expo across a breaking major boundary, so this is a dependency risk report, not a recommendation to run that fix.

27. **[WARN] The local settings cache bypasses the validation used for Supabase settings.** Remote settings are range/type checked in `src/lib/api.ts:133-147`, while local settings are merged directly into defaults (`src/lib/local-store.ts:25-43`). A stale or partially incompatible snapshot can introduce an invalid `speechRate`, `pauseLength`, or enum value before the remote refresh completes; downstream audio code indexes settings directly, for example `PAUSE_MS[this.settings.pauseLength]` (`src/lib/rehearsal/line-runner.ts:291-297`).

28. **[WARN] Daily spend caps are not atomic and can be bypassed by concurrency.** Each request sums prior rows before sending a new paid call (`supabase/functions/places-ai/index.ts:201-223`), so simultaneous requests can all pass the check and collectively exceed the cap. The query also truncates at 20,000 rows without an explicit order (`supabase/functions/places-ai/index.ts:204-208`), which can undercount a high-volume day. This does not alter logged per-call costs, but it weakens the app's cost-protection logic.
